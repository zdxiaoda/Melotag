## 4. 必须主动披露的重点

1. **用户内容只在本机，不等于没有 UGC。** 用户可以在应用中查看、编辑、导入、导出和写入自己的歌词与封面。不要在问卷中简单回答“没有用户内容”；应说明“可创建/编辑，但不公开发布、不用户间分享”。
2. **在线结果是第三方内容。** 在线标签匹配、封面搜索和歌词搜索会显示第三方返回的标签、封面和歌词；这些内容可能不准确、包含成人语言或冒犯性图像，应用不做内容审核。用户选择后才应用到自己的文件；批量自动匹配也由用户先配置并启动。
3. **网络请求是有限但真实的。** 在线查询发送搜索文本和常规网络信息（IP、User-Agent）；不上传音频文件、内嵌封面、歌词全文或完整路径。启动时默认向 GitHub Releases 查询版本，可在设置中关闭。
4. **Last.fm key 是可选用户密钥。** 如果用户填写 Last.fm API key，它会以明文保存在本机 `settings.json`，并在使用 Last.fm 源时发送给 Last.fm。这不是 Melotag 账号，但属于用户提供的凭据，应在隐私/数据问题中如实说明。
5. **没有账号、广告、内购、赌博、聊天、位置和用户间分享。** 这些是可以明确回答“否”的项目；不要把“没有账号/广告”扩大成“没有任何网络请求”或“没有任何数据收集”。
6. **不要声称内容全部安全或经过审核。** 应用没有内容审核团队、举报机制或社区准则；用户自己的文件和第三方返回内容不受 Melotag 控制。

## 5. 不建议的回答方式

- 不要回答“没有用户生成内容”——用户可以编辑和保存自己的歌词与封面。
- 不要回答“没有网络功能”或“不收集任何信息”——在线查询和 GitHub 更新检查是实际存在的网络请求。
- 不要回答“所有歌词/封面都经过审核”——应用不审核第三方结果。
- 不要回答“没有暴力/性内容/粗口”——如果题目问的是用户或第三方可能展示的内容，应如实说明应用本身不提供、但不审核第三方结果。
- 不要把本文的“回答方向”当成已经获得的评级，也不要在 IARC 证书签发前在 listing 或宣传中写具体分级。
- 不要提供虚构的测试账号、密码或年龄验证信息；本应用不需要账号即可测试。

## 6. 提交后的处理

1. 在 Partner Center 完成 IARC 问卷并提交。
2. 保存 IARC 返回的评级/证书信息，再填写商店年龄分级字段。
3. 如果 IARC 追问用户内容或第三方内容，按第 1、3、4 节的事实说明，不要为了获得更低分级而缩小披露范围。
4. 如果最终评级与预期不同，先复核问卷答案和 listing 描述，再提交认证；不要直接把本文档当作评级依据对外展示。
5. 在证书签发前，不要在 listing、README、认证备注或对外沟通中声称已获得任何评级。
