# MusicTag v1.0.9.0 功能清单与复刻方案

> 依据：纯静态逆向结果（REA 元数据/调用边 + 1,813 条明文 `#US` 字符串 + 设置键名 + SQL 原文 + 原生 DLL 的 RTTI 类型名 + P/Invoke 映射）。
> 文中"已证实"= 在二进制里直接看到；"推断"= 由多条线索推出；"未知"= 静态看不到、复刻时必须自测。
> 复刻建议全部为**独立实现**，不复用原程序的任何二进制、图标、二维码图片或成段文案。

---

## 0. 一句话架构

原程序 = **WinForms 前端（.NET Framework 4.6.1）** + **原生标签引擎（改名后的 TagLib C++ 分支）** + **MediaInfo 20.08（技术参数）** + **SQLite（历史/撤销与配置）** + **多个在线元数据源适配器（HTTP/JSON/XML）**。

复刻时最省力且合法的路线：**.NET 8 + WinForms/Avalonia + TagLib#（或 P/Invoke 官方 TagLib C++）+ MediaInfo.DotNetWrapper + Microsoft.Data.Sqlite + System.Text.Json**。

## 1. 功能全景

### 1.1 主窗口

单窗口 + 底部状态栏 + 顶部工具栏 + 菜单栏；文件以列表（ListView，可配置列、可排序）展示，支持多选与拖放。

- 工具栏按钮（按原键名还原，共 15 组）：添加目录、切换目录、管理目录、读取标签、保存、批量另存为 LRC、批量自动匹配标签、批量文件名相关、批量提取封面、移除标签、刷新、全选、取消全选、选项、标签历史、撤销、歌词源、封面源、组合标签源、字符集、简繁转换、退出。
- 状态栏：全部文件数、选中文件数、当前过滤条件输入框（快速过滤）。
- 托盘：可最小化到通知区（`MinimizeToNotiArea`、`AlwaysShowIconInNofiArea`），托盘菜单含退出。
- 窗口几何记忆：`MainFormPosSizeInfo`、`FormPosSizeInfo`（位置/大小/最大化状态按窗体分别保存；带双屏越界修正）。

**列**（内置字段 + 可自定义）：文件名/路径、标题、艺术家、专辑、专辑艺术家、年份、音轨、碟号、流派、注释、作曲、作词、歌词、封面、格式、时长、比特率、采样率、声道、文件大小、状态。列宽/顺序/显隐存 `ListviewColumnHeader`，自定义列存 `customcolumns`。

### 1.2 文件与目录

| 功能 | 行为要点 |
|---|---|
| 添加文件/文件夹 | 支持多选文件、递归子目录（`subdirectories` 开关）、拖放到窗口 |
| 目录管理 | 维护一个"常用目录"列表（`manageDirs`），可添加/删除/切换当前目录（`chgDir`） |
| 刷新 | 重新读取当前列表项的标签与文件属性 |
| 移除 | 仅从列表移除（`RemoveItems`），可选同时删除文件（`Msg_ConfirmRemoveFiles`、`Msg_DeleteFilesCompleted`） |
| 打开位置 | `shell32.SHOpenFolderAndSelectItems` 定位到资源管理器 |
| 过滤 | 扩展名白名单（`RestrictFileExts`）、按时长过滤（`FileFilterByDuration` + 列表）、忽略视频文件（`FileFilterIgnoreVideoFile`）、关键字过滤（`FilterListViewType/Keyword`） |
| 查找 | 查找下一个/上一个（`FindNext/FindPrevious`）、查找替换（`FindOrReplace`）、结果为空有提示（`Msg_CannotFindText`） |
| 选择 | 全选、取消全选、反选 |

### 1.3 标签读取 / 编辑 / 保存

- 读取单文件、选中文件、全部文件；读取后填入列表与"标签编辑面板"。
- 编辑面板按字段分块：标题/艺术家/专辑/专辑艺术家/年份/音轨/碟号/流派/注释/作曲/作词 + 歌词多行框 + 封面预览框。
- 字段级来源标记：每个字段可显示取自哪个在线源；可"从本地文件标签复制"（`ChooseFromFileTags`）。
- 保存：整批保存（`CommonSaveTags`），逐文件报告成功/失败/跳过（`Msg_OK_Fail_Count`、`Msg_OK_Fail_Skip_Count`）。
- 只读文件：提示是否去掉只读属性（`Msg_WantAllowRemoveReadonlyAttribute`）。
- 保留文件修改时间（`SaveTagsKeepUpdateTime`）。
- 写标签时可选同时写 LRC（`SaveLrcWhileSaveTags`）。
- ID3v2 版本可选（`ID3v2Version`，通常 2.3/2.4）。
- 可选把网易云 `163key` 写入 comment（`CommentTagWrite163Key`）。
- 不支持多音轨的音频文件（`Msg_InvalidFileWithNoSupportMultiTrackAudioFile`）与不支持的扩展名（`Msg_NoSupportExt`）会跳过并计数。
- 移除以编辑：`ClearTags`（单/批量清空）、`RemoveFiles`。

### 1.4 批量自动匹配标签（核心卖点）

1. 选中若干文件 → 触发 `StartAutoMatchTags`。
2. 每个文件按搜索条件生成查询：仅用文件名 / 使用艺术家 / 使用专辑（`SearchCondition_*`）。
3. 并发查询多个源（`AutoMatchTagsWebSearchThreadCount`，默认线程数可配），每个源返回结果上限 `WebSearchItemsLimit`。
4. 结果按源的优先级排序并合并（`CombTagsInfo_SourceItemList`），按覆盖策略写回（`CombTagsSearchOverwriteOptions`：哪些字段允许覆盖、是否覆盖空值）。
5. 匹配失败的项保留原值并计入失败数；可对单文件弹出候选列表手工挑选（`FormCombTagsSearch`）。

### 1.6 歌词子系统

- 搜索（`SearchLyric`）、下载（`DownloadLyric`，含翻译 `tlyric`）。
- 保存为 `.lrc`：默认目录（`SaveLrcDirectory`）、文件名模板（`SaveLrcFilenameFormat`，原程序内部格式串 `{0}{1}.lrc`）、默认编码（`SaveLrcFileDefaultEncoding`，候选列表 `LrcFileEncodings`）。
- 导入 LRC（`ImportLrcFile`，单个/批量 `batchImportLrcFile`）。
- 时间标签处理：重排（`ReformatTimetag`：把多行时间标签拆成逐行）、移除（`RemoveTimetag`）、调整（`FormLyricAdjustTimetag` 对话框做整体偏移）。
- 清理：删除空文本行（`DeleteLinesOfBlankText`）、删除头部标签（`DeleteHeadTag`，如 `[ti:]`、`[ar:]` 段）。
- 简繁转换（`chsToCht/chtToChs`）、重置歌词（`Reset lyric`）。
- 与翻译歌词的连接符（`ConnectorsLyricAndTLyric`）、是否取消原始歌词（`LyricDownload_DownloadTrans_DontDownloadOrigLyric`）。

### 1.7 封面子系统

- 在线搜索（`SearchPicture`）、下载（`DownloadPicture`）、本地选择（`chooseLocalFile`）、从标签导出（`ExtractCover`，批量 `ExtractCovers`）、移除（`removeCover`）、更换分辨率（`changeResolutionCover`）。
- 限制：体积上限 `PictureSizeLimitsKB`、格式白名单 `PictureFormatLimits(+Keys/Entries)`（原生引擎支持的 MIME：`image/jpeg`、`image/png`，另有 `IMAGE/BMP`、`IMAGE/GIF` 常量）、分辨率上限 `PictureResolutionLimits`。
- 封面类型：`cover`/`Front Cover`/`coverTypeToolStripMenuItem`（ID3v2 APIC 的类型序号可选）。
- 覆盖策略：`OverwritePictureboxPicture`（下载的封面是否直接覆盖编辑框）。
- 写回方式：嵌入标签或存为独立文件（内部命名 `{0}{1}-{2}{3}`，即"歌名-类型.扩展名"）；备份路径键 `allpicturedata_path`。

### 1.8 文件名 / 重命名

- 批量重命名（`StartRenameFiles`）或"按文件名反写标签"（`StartChangeTags`）两种模式（`FormFilenameRel` 里 `Operation mode` 二选一）。
- 模板占位符（已证实）：

| 占位 | 含义 |
|---|---|
| `@0` | 不使用（保留原样） |
| `@1` | 标题 |
| `@2` | 艺术家 |
| `@3` | 专辑 |
| `@4` | 碟号 |
| `@5` | 音轨号 |
| `@6` | 年份 |
| `@7` | 注释 |
| `@8` | 专辑艺术家 |

- 预制模式 6 个：`@5. @1`、`@4@5. @1`、`@5. @2 - @1`、`@4@5. @2 - @1`、`@2 - @1`、`@1 - @2`；另有"自定义"。
- 校验规则（原文错误键）：占位不能相邻、不能重复、不能只用 `@0`、必须包含至少一个有效占位、模式不能为空、必须输入自定义模式。
- 正则模式：输入正则 + 把捕获组映射到字段（`1-Track 2-Artist 3-Title …`），要求捕获组编号不重复、非空、必须能匹配；提供示例文本与实时预览；清空捕获组按钮。
- 连带处理：重命名时可选同时重命名关联的 `.lrc` 与图片文件（`Rename related Lrc file and picture file`）。
- 文件名非法字符替换、扩展名保留、前缀/后缀（`is_rename_with_extra`、`FilenameCustomPattern`）。
- 应用后写入历史，可撤销（`UndoRename`）。

### 1.9 标签历史与撤销

- 每次保存/重命名/下载歌词封面后把"文件路径 + 当时标签 + 时间"写入 SQLite；`serial` 由 `config.thserial_prefix` 递增生成（`{prefix}-{n}`）。
- 历史面板（`TagsHistory`）：按文件查看历史记录，可还原到任一历史点（`UndoSaveTags`）、撤销重命名（`UndoRename`）。
- 歌词/封面这类大字段在还原前会另存备份文件（键 `lyrics_path`、`allpicturedata_path`、`tags_history_serial`）。
- 清空历史（含确认）后可 `VACUUM`。
- 数据库版本化：`DatabaseVersion` 支持升级迁移。

### 1.10 简繁转换

## 2. 格式支持矩阵

原生引擎的 RTTI 命名空间给出了它真实的模块划分（这是复刻的关键情报）：

`ID3v1, ID3v2, APE, FLAC, Ogg(Vorbis/Opus), MP4, RIFF, ASF, MPEG, MPC, WavPack, TrueAudio, DSD(DSF/DFF), TAK, AAC, VString/VByteVector/FileRef/…`

> 这套命名空间与类层级（`File/Tag/Properties/Attribute/Picture/…Object`）和 **TagLib C++** 完全一致，只是把 `TagLib` 换成了 `MainT`。也就是说：**原程序的原生标签引擎是 TagLib C++ 的改名分支**，另外自带 `TAK`、`AAC` 等上游没有的命名空间（自定义扩展）。

| 容器 | 标签格式 | 读取 | 写入 | 备注 |
|---|---|---|---|---|
| MP3 (MPEG) | ID3v1、ID3v2.3/2.4 | ✅ | ✅ | `ID3v2Version` 决定写入版本；可选 APEv2 |
| FLAC | VorbisComment + FLAC PICTURE | ✅ | ✅ | 封面原生支持 |
| Ogg Vorbis / Opus | VorbisComment（+ METADATA_BLOCK_PICTURE） | ✅ | ✅ | |
| APE (Monkey's Audio) | APEv2 | ✅ | ✅ | |
| WavPack | APEv2 | ✅ | ✅ | |
| TrueAudio (TTA) | ID3v1/v2 + APEv2 | ✅ | ✅ | |
| Musepack (MPC) | APEv2 / ID3v2 | ✅ | ✅ | |
| WAV (RIFF) | RIFF INFO + ID3 chunk | ✅ | ✅ | |
| AIFF (FORM) | ID3v2 | ✅ | ✅ | |
| MP4 / M4A | `moov.udta.meta.ilst`（`©nam/©ART/©alb/trkn/disk/gnre/covr/…`），AAC/ALAC 属性 | ✅ | ✅ | 封面存 `covr` |
| WMA / ASF | ASF 属性对象（`ContentDescription`、`ExtendedContentDescription`、`Metadata`、`MetadataLibrary`、`Picture`） | ✅ | ✅ | 引擎有完整 ASF 对象模型 |
| DSF / DFF (DSD) | ID3v2（DSF 有 ID3 指针块；DFF 有 ID3 chunk） | ✅ | ✅（引擎有 DSD/DSF/DFF 类，写入路径需实测） | |
| TAK / AAC | 引擎存在命名空间 | 未证实 | 未证实 | UI 未宣传，可能仅内部/实验 |
| 多音轨音频 | — | 拒绝 | — | 明确提示不支持 |

技术参数（格式/时长/比特率/采样率/声道）由 **MediaInfo 20.08** 提供（原生层 `LoadLibrary` 后 `GetProcAddress` 调用 `MediaInfo_*`），标签字段由 TagLib 分支负责。

## 3. 数据模型（复刻建议）

```csharp
public sealed record TrackFieldSet
{
    public string? Title { get; init; }
    public string? Artist { get; init; }
    public string? AlbumArtist { get; init; }
    public string? Album { get; init; }
    public uint? Year { get; init; }
    public uint? Track { get; init; }
    public uint? TrackCount { get; init; }
    public uint? Disc { get; init; }
    public uint? DiscCount { get; init; }
    public string? Genre { get; init; }
    public string? Comment { get; init; }
    public string? Composer { get; init; }
    public string? Lyricist { get; init; }
    public string? Lyrics { get; init; }
    public string? TranslatedLyrics { get; init; }
    public IReadOnlyList<Picture> Pictures { get; init; } = [];
}

public sealed record Picture(byte[] Data, string MimeType, string Description, PictureKind Kind);

public sealed record AudioInfo(string Format, TimeSpan Duration, int? BitrateKbps,
                              int? SampleRateHz, int? Channels, long FileSize, bool IsMultiTrack);

public sealed class TrackItem
{
    public required string Path { get; init; }
    public TrackFieldSet Tags { get; set; } = new();
    public AudioInfo? Info { get; set; }
    public ItemStatus Status { get; set; }          // Pending/Read/Modified/Saved/Failed/Skipped
    public string? LastError { get; set; }
    public bool IsSelected { get; set; }
    public Dictionary<string, string> SourceHints { get; } = new(); // 字段来自哪个源
}
```

字段来源标记（原程序有"字段级来源"显示）建议保留为 `Dictionary<FieldKey, SourceId>`，用于"覆盖策略"和 UI 展示。

## 4. 关键算法（可直接照此实现）

### 4.1 模板占位符

```csharp
public static class NamePattern
{
    // @0 不使用；@1 标题；@2 艺术家；@3 专辑；@4 碟；@5 音轨；@6 年；@7 注释；@8 专辑艺术家
    public static string Render(string pattern, TrackFieldSet t, string? extension, bool keepOriginalWhenEmpty)
    {
        var map = new Dictionary<char, string?>
        {
            ['1'] = t.Title, ['2'] = t.Artist, ['3'] = t.Album,
            ['4'] = t.Disc?.ToString(), ['5'] = t.Track?.ToString("00"),
            ['6'] = t.Year?.ToString(), ['7'] = t.Comment, ['8'] = t.AlbumArtist,
        };
        var sb = new StringBuilder();
        for (var i = 0; i < pattern.Length; i++)
        {
            if (pattern[i] == '@' && i + 1 < pattern.Length && map.ContainsKey(pattern[i + 1]))
            {
                var key = pattern[i + 1];
                var value = map[key];
                sb.Append(string.IsNullOrWhiteSpace(value) && keepOriginalWhenEmpty ? key.ToString() : value);
                i++;
            }
            else sb.Append(pattern[i]);
        }
        return Sanitize(sb.ToString()) + extension;
    }

    // 校验：非空、含有效占位、不含 @0 单独使用、占位不重复、占位不相邻
    public static IReadOnlyList<string> Validate(string pattern) { /* … */ }
}
```

`Sanitize` 处理 `\ / : * ? " < > |` 与首尾空格、保留设备名（CON/PRN/AUX/NUL/COM1…），并按原程序行为保留扩展名。

### 4.2 正则捕获组映射

```csharp
public sealed record RegexPlan(Regex Pattern, IReadOnlyDictionary<int, FieldKey> GroupMap);

public static bool TryApply(RegexPlan plan, string fileNameWithoutExt, TrackFieldSet target, out TrackFieldSet result)
{
    var m = plan.Pattern.Match(fileNameWithoutExt);
    if (!m.Success) { result = target; return false; }
    var updated = new Dictionary<FieldKey, string?>();
    foreach (var (group, field) in plan.GroupMap)
        if (group > 0 && group <= m.Groups.Count && m.Groups[group].Success)
            updated[field] = m.Groups[group].Value.Trim();
    result = Apply(target, updated);   // 只覆盖映射到的字段
    return true;
}
```

原程序的校验点（照抄语义即可）：捕获组编号不能重复、不能为空、不能映射到"不使用"、必须能匹配示例、模式不能为空。

### 4.3 合并与覆盖策略

```csharp
public enum OverwriteRule { Never, IfEmpty, Always }

public static TrackFieldSet Merge(TrackFieldSet current, TrackFieldSet candidate, OverwriteOptions opts)
{
    TrackFieldSet Pick(TrackFieldSet a, TrackFieldSet b) => new()
    {
        Title      = Choose(a.Title,      b.Title,      opts.Title),
        Artist     = Choose(a.Artist,     b.Artist,     opts.Artist),
        Album      = Choose(a.Album,      b.Album,      opts.Album),
        // … 每个字段一条
    };
    static string? Choose(string? cur, string? next, OverwriteRule rule) => rule switch
    {
        OverwriteRule.Always  => next ?? cur,
        OverwriteRule.IfEmpty => string.IsNullOrWhiteSpace(cur) ? (next ?? cur) : cur,
        _                     => cur ?? next,
    };
    return Pick(current, candidate);
}
```

### 4.5 歌词处理流水线

```
抓取 → (可选)取翻译 → 合并原文/译文 → 时间标签处理 → 去空行 → 去头部标签
     → 简繁转换 → 选择编码 → 写 .lrc 或写回标签
```

- **重排时间标签**：`[mm:ss.xx]A\n[mm:ss.xx]B` 中一行含多段时间标签时，按行拆分并把最后一段时间应用到该行。
- **移除时间标签**：删掉所有 `[..]` 前缀。
- **整体偏移**：解析所有时间戳后统一加减偏移量，处理负值与小时进位。
- **去头部标签**：删除 `[ti:][ar:][al:][by:][offset:]` 这类元信息行（`[00:12.34]` 形式的正文时间轴必须保留——用正则区分）。
- **编码**：候选 `LrcFileEncodings`（UTF-8/UTF-8 BOM/GBK/UTF-16 等）；写入时按设置。

### 4.6 封面处理

```
候选图 → 过滤(格式白名单 → 分辨率上限 → 体积上限)
      → 缩放/重编码(JPEG 质量可调) → 写回标签(APIC/PICTURE/covr/ASF Picture)
      → 或另存 "{歌名}-{类型}.{ext}"
```

原程序对超限图片做的是"压缩失败则提示"（`Msg_CompressPictureFail`），复刻可用 `System.Drawing`/`ImageSharp` 实现等比缩放 + 质量递减重试。

### 4.7 历史与撤销

```sql

    serial      TEXT PRIMARY KEY,              -- "{prefix}-{n}"
    filepath    TEXT NOT NULL,
```

- 撤销 = 读历史行 → 还原字段 → 若歌词/封面来自备份文件则从备份恢复 → 再写一次标签并记录新历史。

- 大字段（封面）不要塞进 SQLite 行里，按原程序做法存到备份目录并在行里记路径。

## 6. 复刻时最容易踩的坑

1. **别用原程序的图标、二维码、文案、字体文件**（`fontawesome-webfont.ttf` 是第三方 OFL 字体可另取；二维码是作者收款码，绝对不要复用）。
2. **不要把原生 `MusicTag.dll` 当依赖**：它是改名后的 TagLib 分支二进制，直接调用等于复用他人构建产物；请自己编译 TagLib 或用 TagLib#。
3. **DSD 写入**：TagLib 上游对 DSF 支持较新，DFF 视版本；务必用样本实测，不要假设。
4. **多音轨文件**：原程序直接拒绝；复刻若想支持，需要定义"编辑第几轨标签"的语义。
5. **WAV/AIFF 的标签**：RIFF INFO 与 ID3 chunk 并存时优先级要与读取端一致，否则会出现"写完读不到"。
6. **MP4 的 `trkn/disk` 是成对整数**，不是字符串；年份在 `©day`。
7. **ID3v2.3 vs 2.4**：2.3 不支持 UTF-8 帧，CJK 需 UTF-16；原程序提供该开关正是为此。
8. **在线源合规**：见 §10。

## 8. 合规与风险（复刻前请读）

1. **功能与思路可以借鉴，代码与素材不能照搬**：原程序未声明开源许可；不要复制其图标、界面截图、二维码、整段文案、二进制模块。
2. **在线源**：Last.fm、MusicBrainz、iTunes、网易云、QQ、酷我、酷狗、虾米各有服务条款；其中多个**没有公开 API 或明确禁止第三方抓取**。原程序对虾米伪装客户端 UA 的做法属于规避性访问，复刻时**不要照做**。
   - 合规替代：Last.fm 官方 API（需自申请 key）、MusicBrainz 官方 API（遵守 1 req/s 与 User-Agent 规范）、Cover Art Archive、iTunes Search API、AcoustID、Discogs API。
   - 若做中文曲库，优先申请商业 API 或让用户自填，而不是逆向其私有接口。
3. **简繁转换**：用 OpenCC 等开源实现，别抄其内置映射表。
4. **作者权益**：这是一个个人开发者维护的免费软件（靠捐赠）。若你的复刻面向公开发布，建议先联系作者说明意图；至少不要使用其名称、图标与界面文案造成混淆。
5. **隐私**：复刻若保留"标签历史"功能，务必提供一键清空，并明确告知会记录本地文件路径。
